### 6. 本地 vLLM 模型 SVG 生图打通（2026-06-11 下午）
- 需求：用 `.env` 中配置的本地 qwen3.6-35b vLLM 模型生图
- 问题：`image_gen.py` 无法直接用，因为：
  1. `IMAGE_BACKEND=qwen3.6-35b` 不是合法后端名（应是 `qwen`、`openai` 等）
  2. vLLM 只提供 `/v1/chat/completions`，没有 `/v1/images/generations`
- 解决方案：新建 `scripts/svg_gen.py`
  - 直接用 chat completions API + 精心设计的 prompt，让模型输出 SVG 代码
  - 从响应中提取 `<svg>...</svg>` 并保存为 .svg 文件
- 修复 `.env`：`QWEN_BASE_URL` 从 `https://` 改为 `http://`（vLLM 端口 8000 是 HTTP）
- 测试通过：成功生成 architecture_gen.svg，含用户→API Gateway→Qwen3.6 架构图
- 结论：`.env` 配置本身可用，问题只在 `image_gen.py` 的后端注册表不支持自定义 chat 模型名

### 7. image_gen.py fallback — qwen36-svg 后端集成（2026-06-11 下午）
- 需求：当没有真正的生图模型可用时，image_gen.py 自动 fallback 到 SVG 方案
- 方案：新建 `image_backends/backend_qwen36_svg.py`，作为标准后端注册到 BACKEND_REGISTRY
- 调用链：image_gen.py → backend_qwen36_svg.generate() → vLLM chat API 生成 SVG → svglib+renderPM 转 PNG
- 接口完全兼容现有后端：generate(prompt, aspect_ratio, image_size, output_dir, filename)
- 注册为 `qwen36-svg`，别名 `local`、`qwen-svg`
- .env 更新：IMAGE_BACKEND=qwen36-svg（替代无效的 qwen3.6-35b）
- 测试通过：单图模式、manifest 批量模式均正常生成 PNG（1067x1067 ~ 1707x960）
- 已知限制：svglib 不支持 SVG 渐变（flat color fallback），PNG 质量降低但 PPTX 兼容
- svg_gen.py 脚本保留在 skills/deepppt/scripts/，作为独立工具；image_gen.py 现在是主入口
